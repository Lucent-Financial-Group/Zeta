## Description

> Aaron 2026-09-12: *"yes we need timeouts cause agents often forget to release locks."*

`isRunning` asks the OS whether a pid is alive, which answers the **crash** case and nothing else. A holder that is alive but wedged — a stalled read, a stopped process, an agent that never called `release` — reads alive forever, and the lock is obeyed forever with it.

### No protocol change was needed

`exclusive-lock.ts` already takes staleness as the **caller's predicate**, and the owner record already carries `startedAt`. So the deadline is a stricter predicate and nothing else: a holder must now be running **and** inside its hold window. Two hours by default, `ZETA_STORE_LOCK_MAX_HOLD_MS` to override.

### Why takeover is safe here — argued, because in general it is not

A lease without a fencing token converts *stuck forever* into *silent double-write* (Kleppmann, 2016). I said that before checking. Checking changed the answer: **this store cannot interleave.** Every event is written as its own shard whose **filename is its content address** (`identifyEvent`), and `readEvents` orders by the event's own `atMs`, never by filename.

- two byte-identical events → same address → collapse
- two **different** events → different addresses → **both survive**

No file is shared between writers, so two concurrent runs produce a **union** — two versions somebody can compare, which is exactly the cost of duplication Aaron named.

### The one shared-append target, named rather than left to be found

The cost ledger on #17299 does `appendFileSync(join(store, <date>.jsonl), line + NL)` — one file per day, every run. `O_APPEND` writes under `PIPE_BUF` are atomic on POSIX so lines almost certainly land whole, **but nothing in the repo states that bound or checks a line against it.** If that ledger carries a long enough line, or moves off `O_APPEND`, this deadline stops being safe alone and needs the generation fenced at the resource — 081M2B02991087G0R002XYKG54 now has a concrete first caller.

### Two decisions worth disagreeing with, both stated in the source

- **An unparseable `startedAt` expires** rather than being obeyed. Obeying it makes one malformed record a permanent wedge — the thing this removes.
- **A holder whose clock is ahead** yields a negative age, **clamped at zero**, so skew cannot buy an unbounded hold. Cross-machine skew is acceptable in this one place because the comparison decides a *local* action, which `local-time-never-enters-the-shared-fold` explicitly permits.

### Falsifiers

8 tests including a **control** (a live holder *inside* the deadline is still refused — without it, a deadline of zero would pass everything and the lock would exclude nothing). **5 mutants, 5 killed:** deadline dropped from the predicate · unparseable obeyed · boundary made exclusive · negative-age clamp removed · malformed env read as zero.

One existing fixture changed: `watch-org.test.ts` planted a live holder at a **fixed past instant**, which under a deadline is stale by age — it was encoding "any live pid blocks, forever". Now a current timestamp, so it still tests the live-holder path it exists for.
