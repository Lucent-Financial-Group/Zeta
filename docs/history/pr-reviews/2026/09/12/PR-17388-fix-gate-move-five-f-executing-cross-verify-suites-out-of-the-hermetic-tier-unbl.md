## Description

## What broke

PR #17341 bumps the `global.json` SDK pin 10.0.400 → 10.0.401. `gate (required)` went red
because `test (TS hermetic)` failed, and it failed because **five suites in that tier execute
F# through `dotnet`/`fsi`, which the hermetic tier does not provision**:

- `nonquotient-adinkra-halfspin-decomposition-cross-verify.test.ts`
- `nonquotient-adinkra-halfspin-intertwiner-fsharp-cross-verify.test.ts`
- `nonquotient-half-spin-bracket-fsharp-cross-verify.test.ts`
- `multilayer-bnn-online-update-cross-verify.test.ts`
- `reference-frame-heterarchy-cross-verify.test.ts`

`bunfig.hermetic.toml` says so itself, in its own contract: the tier is red when the source
or the declared baseline is broken — *"Not if you have no .NET SDK."*

They were green for as long as the `ubuntu-24.04` image happened to ship the SDK
`global.json` named. The bump outran the image and all five went red at once. **This is the
first time the tier boundary was ever tested** — a check passing on a coincidence of the
runner image is one that did not really run looking like one that passed.

## Tier and floor are different questions

The obvious home is `test (TS environment-dependent)` — it provisions the SDK. **Right tier,
wrong floor:** that job is *not* in `gate (required)`'s `needs`. Landing them there would
have removed five oracle checks from the blocking set while a commit message truthfully
reported that the tests still run. They would still *run*; they would no longer *block*.

`full-verify (7-lang oracle + cost + proofs)` is **in the floor and has the full toolchain**,
and these are cross-language oracle tests — so it is the one home that changes neither
property. That is where they now run.

## One thing deliberately not done

The registry entries do **not** restate the SDK version. Three existing entries say
`10.0.302` while `global.json` says `10.0.400` — a roster that copies a pinned value ages out
of agreement with it silently. The new entries name `global.json` as the source instead.

Unblocks #17341.
