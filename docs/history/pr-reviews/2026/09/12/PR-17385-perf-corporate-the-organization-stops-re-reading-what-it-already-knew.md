## Description

## What this is

Seven commits on the same theme: **the organization re-reads things it already knew**, and that is what a run costs.

The whole cost ledger, agentic-tpm + dev-portal, 2026-09-11..12 — 94 calls, $242.53:

| mode | calls | turns | avg/call | usd |
|---|---:|---:|---:|---:|
| follow-up | 59 | 1081 | 18 | 102.03 |
| review | 15 | 1084 | **72** | 100.32 |
| check-answers | 7 | 218 | 31 | 18.58 |
| describe | 7 | 208 | 30 | 16.53 |
| plan-round | 6 | 70 | 12 | 5.07 |

A review costs **four times the turns** of the follow-up whose work it judges, off a quarter of the calls. And 156 tokens are READ for every one written — so what a session has to discover for itself is most of the bill. Every change below removes a reason something gets discovered twice.

## The fixes

**1. A round remembers what it tried.** A reopen dropped the settlement — an open item has none — and dropped the *work* with it. The next session was told "this was turned back, here is why" and nothing about what had already been done, so it re-derived the same diagnosis from the same repository and arrived where the last one did. The settlement now moves onto `attempts` with what became of it, and the session is handed the last few.

**2. A green suite at a commit is not run again at that commit.** `verify.log` shows the same two suites — 81-88s of jest plus 7-8s of vitest — re-run round after round on the same two branches: a turned-back round leaves its commits unpushed, so the next round verifies an identical tree from scratch. The receipt lives in the checkout's own `.git`, because `watch-org` spawns a fresh `run-org` each tick and anything in memory dies with it. Only a pass, only a clean tree, only the verifier that produced it.

**3. The verifier was still blocking.** It called `spawnSync` — the same defect the follow-up port had, on the longest-running command here. For ~90 seconds nothing else in the run could proceed: not another item's session, not a poll, not the queue meant to run three at a time. The answerer, reader and commenter were blocking too. All four awaited now.

**4. The log is read once per process, not twenty-two times.** 17,169 event files, 64MB — and `run-org.ts` calls `readEvents` 22 times, four behind `get` accessors that re-read on *every property access*. The fold was never the expensive part. Memoised, dropped on every append so a run still sees its own writes; `watch-org` and `serve-org` call `forgetEvents` because another process writes their store.

**5. A review is handed what changed.** The first several turns of every review are "what changed, and which of those are tests". One `git diff --name-only`. Run once here instead of paid for at 72 turns a call.

**6. The hat that answers a reviewer wakes up knowing what the hat that wrote the code learned.** The memory circuit reached the original work walk and stopped. Both halves reach the follow-up seam now — what it knows, and credit for what it says it relied on.

**7. A round may ask for a stage its chain does not owe.** `gatesForRound` already let the organization decide; `available` was capped at the item's chain, so a follow-up touching authentication could never ask for a security review. Offered when the chart holds an independent owner, and naming one is recorded as the decision it is.

## Bugs fixed along the way

- **One flag drove two unrelated knobs.** `--supply-target` set wearers per hat *and* how many requests a run follows up. `--follow-up-at-once` now means only the second; absent, the old flag still sets both, so every existing profile is unchanged.
- **`merged`/`closed` had never been consumed.** The poller has reported them since it was written — zero events ever read them. So "the merge request was merged" became an action item for a session to *decide about*, and `foldHandedOffChanges` only ever grew: every request ever handed off was polled again on every tick, for ever.
- **Reviewer scratch worktrees leaked.** Cleanup depended on the agent remembering. The organization names the path and removes it now, whatever the session did.
- **A cwd-sensitive fixture was failing five tests.** `git-data-source.test.ts` took `process.cwd()` for the repo root, which it is only when the suite is run from there. The adapter was right every time.

## Not included

- `--verify-at-once` defaults to **1**, exactly the critical section it replaces. Widening it is the operator's call because two of agentic-tpm's suites fight over the MongoMemoryServer port — a fact about that repository, not about the organization. Each concurrent run gets a slot to allocate ports from when they do widen it.
- Moving checkouts off the synced folder. The run now *says* what is watching its files, with the path, and never refuses — where somebody keeps their work is their decision. The direction is not in doubt; the size is unmeasured and nothing here claims a number.
