## Description

> Aaron, 2026-09-12: *"we also want ace to be able to install the updates too, not just notice it's out of date. we also want ace to be much deeper and queue the AIs to what other files might need to bump with the deps bump."*

`ace` has the **observation** half (`ace outdated`) and the **judgement** half (`dep-update/toy-classify`). It has no **apply** and no **coupling**.

### The measurement — every bump on 2026-09-12 forced edits elsewhere

Each edge was found by a separate CI failure, *after* the PR was already red:

| bump | files that had to move **with** it |
|---|---|
| `dotnet-sdk` 10.0.400→401 | `.mise.toml`, `global.json`, `mise.lock`, **and** a `cross-verify` leg running F# with no SDK |
| `numpy` 2.5.1→2.5.3 | the carrier, `CARRIER_FINGERPRINT` (Python), `CarrierFingerprint` (**F#**, pinned separately), 2 receipts |
| any GitHub Action | `action-sha-roster.json` (derived) |
| `FSharp.Core` | 63 `packages.lock.json` + a pinned hash inside an audit |

Roughly a dozen red check-runs and most of a day — for four bumps whose coupled edits were **all knowable from the diff alone**.

### The couplings are already written down — as refusals

```
.mise.toml <-> global.json          audit-dotnet-pin-parity.ts
.mise.toml <-> mise.lock            audit-mise-lock-coverage.ts
workflows  <-> action-sha-roster    audit-action-sha-roster.ts
carrier    <-> two fingerprints     the fixture + MiniGridEmpty5x5Adapter.fs
lock files <-> nuget.org provenance audit-fsharp-core-comes-from-nuget-org.ts
```

An audit states the relation **backward and late** — *"A and B disagree"*, after the edit, as a refusal. Read **forward** it is exactly the queue ace needs: *"you touched A, so B must move."*

So the graph should be **derived from the audits**, not authored beside them — the same discipline that makes `action-sha-roster.json`, `build-graph.json` and `UNHASHED-DEPENDENCIES.md` derived-and-committed, so a second copy cannot drift from the first. A hand-written coupling table *would be* that second copy.

### An edge with no audit is `unknown`, never absent

Load-bearing, not decorative. The SDK bump's **fourth** coupling — a `cross-verify` leg spawning `dotnet fsi` with no SDK provisioned — had **no audit at all**. A graph derived only from audits would have reported three edges and been silently wrong about the fourth.

**Falsifier:** replay 2026-09-12 as a fixture. `ace update` must name the coupled files *before* any CI run. The dotnet case is the sharp one — reporting 3 and staying silent about the CI leg scores 3/4 **while claiming completeness**, and fails. It must report the fourth as unknown.

### On the Dependabot CLI

`brew install dependabot` (github.com/dependabot/cli) computes the proposed diff locally, in a container, from the same `.github/dependabot.yml`. That is the small slice: it answers *what would change*, says nothing about *what else must change*, and does not apply. Worth having as a **second meter** on ace's proposals — not a replacement.
