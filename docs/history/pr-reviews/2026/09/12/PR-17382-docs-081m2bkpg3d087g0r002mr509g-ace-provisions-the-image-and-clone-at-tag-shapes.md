## Description

> *"can we make all other tests rely on a docker image of ours with install.sh already installed?"*
> *"maybe we spend a bit of time to move our image to use ace over install.sh … we could eventually make install.sh use ace binaries too."*

### The cost being removed is measured, not assumed

Runtime provisioning is why the repo carries all of this:

| cost | why it exists |
|---|---|
| 561 MB of `.deb` per ubuntu job at ~1.1 MB/s | apt at run time |
| the `apt-archive-cache` action | mitigating that download |
| a 420 s apt budget + `PRE_APT_RESERVE_SECONDS` | bounding it |
| `apt-job-timings.measured.json` + p90 refresher | proving it fits each timeout |
| the slim/standard/full tier roster | limiting per-job installs |
| **four coupled edits on #17341 today** | **one** job joining that governed class |

A prebuilt image deletes the *cause*. The `cross-verify` leg that started #17341 would have needed no provisioning at all.

### The third part walks into a live falsifier — by design

`.claude/rules/clone-at-tag-stays-sufficient.md` anticipated this move **by name**:

> *"never 'until ace ships'… ace may be the **good** path… the moment it becomes the **only** path, it is an appointed hub. The discriminator is **exit, not degree**."*

And `lint-clone-at-tag-is-sufficient.ts` refuses `ace` as a **resolver** in `tools/setup` and `.github/workflows`. So *"install.sh uses ace"* is not free.

Sorted against it — a **shape** constraint, not a refusal:

| part | verdict |
|---|---|
| image provisioned by ace | **fine** — an image is an optimisation; a clone-at-tag consumer never touches it |
| one-line ace binaries | **fine** — distribution, not resolution |
| install.sh uses ace | **only as a fast path with a working fallback** |

…and the fallback must be **exercised on a schedule**, not merely written. A fallback nobody runs is the vacuity class wearing exit's clothes.

### This is what finally makes the rule testable

That rule states its own limit today: the real falsifier is *"clone at a tag with no `ace` on PATH and build"*, which **"cannot run until a second repo exists."** Publishing ace as a separately-installable binary creates exactly that world. So this work doesn't merely have to *respect* the rule — it's what lets the proxy lint be replaced by the real test, and that replacement belongs in the same change that ships the binaries.

### Staleness: a baked image is a frozen judgement

It's a crystal in the sense of #17380 — so it has the crystal's failure mode. An input changing without a rebuild is a **broken meter**: frozen and inspectable in appearance, drifting in fact. Guard the same way — rebuild on declared-input change, pin by **digest** (`pinned-refs` already does this for containers with `update=follow-tag` + `remeasure=`), and make a missed rebuild loud.

### Scope limit, stated

Nothing for macOS/Windows — and `build-and-test` across five platforms is where much of the apt cost actually lands. The win is the Linux-only lint/audit/cross-verify jobs: most of the job count, not the wall-clock-heaviest matrix.

### Falsifiers

1. **Exit is real** — clone at a tag, no `ace`, no image: the tree still builds and the floor still runs.
2. **The fallback is exercised** — a scheduled lane runs the no-ace path and goes red if it rots.
3. **The image cannot silently drift** — changing a declared input without rebuilding fails a check.
