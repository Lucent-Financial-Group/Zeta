## Description

Takes the `numpy 2.5.1 → 2.5.3` bump that #17343 could not, by **re-running the experiment** rather than freezing the dependency.

> Aaron: *"what carrier, can we not just rerun whatever on the latest pin?"*

Yes — and it produces information rather than silence.

### What the replay showed

Run under numpy 2.5.3 against a carrier patched only in that field:

```
steps identical : True
seeds identical : True
digest identical: True
upstreamCommit  : True
fields differing: ['numpy']
```

The recorded trajectory **does not depend on the numpy patch version**. That is a fact worth having, and the ignore-list alone would have thrown it away.

### What a re-record costs — five artifacts, two independent fingerprints

| # | artifact | why it moved |
|---|---|---|
| 1 | carrier `fixtureRuntime.numpy` | the recorded runtime |
| 2 | `CARRIER_FINGERPRINT` (Python) | pins the carrier's bytes |
| 3 | `CarrierFingerprint` (**F#**) | the F# oracle pins it **independently** |
| 4 | python receipt | regenerated by running the replay |
| 5 | fsharp receipt | byte-identical to (4) — the cross-oracle lock |

Both receipts were **regenerated by running the fixture**, never hand-edited; `verify_canonical_receipt` accepts the result.

**(3) is worth recording:** after updating the Python side I ran the F# oracle and it failed **6 of 9**. That is the four-oracle discipline working exactly as designed — each oracle pins the carrier separately, so a partial re-record cannot pass. Had I run only pytest I would have reported this green and shipped a half-updated byte-lock.

**Python 7/7 · F# 9/9.**

### Relationship to the ignore that just landed

#17367 put `minigrid`/`gymnasium`/`numpy`/`pygame-ce` on dependabot's ignore list, which is why #17343 auto-closed. That stays, and the two are consistent rather than contradictory: the ignore stops a **bot** opening PRs it can never make green, and its own `LIFTS WHEN` says a human re-runs the adapter and commits the result. **This PR is that LIFTS WHEN being exercised.**

### The design consequence is filed separately

**#17372** (081M2B8EF75087G0R002YPM4SZ): the F# oracle cannot observe numpy — it *transcribes* the string from the carrier — so byte-equality on that field proves only that both oracles read the same file, and a third oracle using a different numeric library could not honestly participate. This PR pays that cost; that row proposes removing it.
