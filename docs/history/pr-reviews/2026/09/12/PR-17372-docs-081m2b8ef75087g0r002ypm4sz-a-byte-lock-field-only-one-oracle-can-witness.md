## Description

> Aaron, 2026-09-12: *"i don't like having 3rd party libaries needing to be the same across languages for our byte lock agreements, what happens when we want to use something other in numpy in another oracle?"*

The MiniGrid receipt divides into two kinds of field, and only one is an agreement.

**Independently computed — the lock is real.** `MiniGridEmpty5x5Adapter.fs` genuinely simulates the grid (`directionDelta`, initial/goal positions, the forward transition), so positions, reward bits, digests and the upstream commit are derived **twice, by two implementations**. That is the independent-redundancy evidence the four-oracle discipline exists to buy.

**Transcribed — the lock is vacuous.**

```fsharp
FixtureNumPy = readString fixtureRuntime "numpy"
```

F# does not run numpy and cannot observe its version — it copies the string out of the carrier and re-emits it. Byte-equality there proves only that both oracles opened the same file. This repo already names the shape: *"the parser cannot distinguish a copied attestation from an earned one."*

### The sharper half: it does not generalise

A Rust oracle would use `ndarray`, a TypeScript one something else. Neither could do anything but **transcribe Python's numpy version**, which it cannot check and which means nothing for it. So the lock is capped at two oracles by a field that contributes nothing to what the lock proves.

### The cost, already measured

Re-recording for a numpy **patch** bump (2.5.1 → 2.5.3) touched **five artifacts and two independently-pinned fingerprints**, and required both test suites — while the trajectory was **bit-identical throughout** (steps, seeds, digest, upstream commit all unchanged; `numpy` the only differing field). It also creates standing pressure *not* to update dependencies: a security cost paid to protect a field that proves nothing.

### The split

| region | contents | byte-locked across oracles? |
|---|---|---|
| **invariant** | environmentId, stateProjection, seeds, steps, positions, reward bits, digests, upstreamCommit, source hashes | **yes** — every oracle derives these |
| **provenance** | python / minigrid / gymnasium / numpy / pygame-ce | **no** — only Python can witness it |

The carrier needs the same split: F# pins its **whole bytes** today, which is exactly why a numpy bump breaks the F# oracle.

**Provenance stays recorded** — it is what tells you *what moved* if a trajectory ever changes. The claim is only that it must not be locked *across* oracles.

### Falsifiers (neither passes today)

- Change a Python-only dependency version → the cross-oracle bytes must **not** change and F# must **not** need re-pinning.
- Add a stub third oracle declaring a **different** numeric library → it must reach byte-equality on the invariant region **without ever naming numpy**.

This PR files the row only; it changes no receipt.
