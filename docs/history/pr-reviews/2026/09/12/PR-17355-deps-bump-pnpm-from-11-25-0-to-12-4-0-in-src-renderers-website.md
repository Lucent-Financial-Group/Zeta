<blockquote>
<h2>pnpm 12.4</h2>
<h2>Minor Changes</h2>
<ul>
<li>
<p>pnpm can now manage npm, Python, and Cargo dependencies in the same workspace. Enable <code>python.enabled</code> or <code>cargo.enabled</code> in <code>pnpm-workspace.yaml</code>, then use <code>pnpm install</code> to install them together.</p>
<ul>
<li>Add Python packages with <code>pnpm add pypi:&lt;package&gt;</code>. pnpm uses <code>pyproject.toml</code>, <code>pylock.toml</code>, and a managed <code>.venv</code>. Frozen and offline installs are supported, and <code>pnpm run</code> and <code>pnpm exec</code> make the environment's executables available <a href="https://redirect.github.com/pnpm/pnpm/issues/14566">#14566</a>.</li>
<li>Add Rust crates with <code>pnpm add crate:&lt;package&gt;</code>. pnpm supports crates.io and custom sparse registries configured with <code>cargo.indexUrl</code>. Registry authentication supports pnpm credentials and, for crates.io, <code>CARGO_REGISTRY_TOKEN</code> or <code>$CARGO_HOME/credentials.toml</code>.</li>
</ul>
<p>Both ecosystems support faster dependency resolution through <code>pnprServer</code>, with local resolution as a fallback when the server does not support it.</p>
</li>
<li>
<p>Added <code>pnpm pipeline [name]</code> to install frozen dependencies and run workspace tasks declared in <code>pipelines</code>. It selects affected projects, runs their task graph, and continues running tasks after a task fails.</p>
<p>Tasks support <code>inputs</code>, <code>outputs</code>, <code>env</code>, and <code>cache</code> settings. Cached results restore task outputs and replay logs. Cargo tasks can reuse local build state between worktrees with <code>tasks.&lt;name&gt;.cargoTargetDir</code>. Set <code>includeWorkspaceRoot: true</code> to include root tasks.</p>
<p>Use <code>pnpm pipeline --dry-run</code> to preview the task graph without installing configuration dependencies or running workspace hooks.</p>
</li>
<li>
<p>Added support for Android on arm64 and x64, FreeBSD on x64, and Linux on ppc64le, s390x, and RISC-V (riscv64 with glibc) <a href="https://redirect.github.com/pnpm/pnpm/issues/14431">#14431</a>, <a href="https://redirect.github.com/pnpm/pnpm/issues/14597">#14597</a>, <a href="https://redirect.github.com/pnpm/pnpm/issues/7582">#7582</a>.</p>
</li>
<li>
<p>Added <code>trustPolicyExcludePrune</code> to automatically remove unused versions and packages from <code>trustPolicyExclude</code> when running <code>pnpm add</code>, <code>pnpm update</code>, or <code>pnpm remove</code>. It is disabled by default. Package name patterns such as <code>@scope/*</code> are kept, and cleanup is skipped when <code>sharedWorkspaceLockfile</code> is <code>false</code>.</p>
</li>
<li>
<p>Added <code>pnpm change check</code> for CI validation of package versions against the <code>versioning.epics</code> bands and <code>versioning.fixed</code> groups in <code>pnpm-workspace.yaml</code>. It reports all violations, including packages that are not part of the current release.</p>
</li>
</ul>
<h2>Patch Changes</h2>
<ul>
<li>
<p>Registry metadata is now kept separate for registries with different URL paths or schemes. This prevents installs from using another registry's package versions or tarball URLs, and keeps metadata fetched over HTTP from being reused for HTTPS <a href="https://redirect.github.com/pnpm/pnpm/issues/13558">#13558</a>.</p>
<p>The first install after upgrading refetches registry metadata. The package store is unchanged. <code>pnpm cache view</code> now shows full registry URLs. Scripts that parse the directory names from <code>pnpm cache list-registries</code> or <code>pnpm cache list</code> need updating.</p>
</li>
<li>
<p>Patches that add build scripts or a <code>binding.gyp</code> now trigger a build, subject to build approval. Unapproved builds appear under &quot;Ignored build scripts&quot; <a href="https://redirect.github.com/pnpm/pnpm/issues/14648">#14648</a>.</p>
</li>
<li>
<p>Build scripts can now be rejected before installing a package with <code>pnpm add --allow-build=!&lt;pkg&gt;</code>, including global installs. <code>pnpm approve-builds &lt;pkg&gt;</code> and <code>pnpm approve-builds !&lt;pkg&gt;</code> also save decisions when no packages are awaiting approval. They warn if the named package is not awaiting approval <a href="https://redirect.github.com/pnpm/pnpm/issues/14067">#14067</a>.</p>
</li>
<li>
<p>A registry configured in <code>.npmrc</code> now takes precedence over registry settings saved by <code>pnpm login</code> in the global <code>config.yaml</code>. This fixes installs using the wrong registry after login <a href="https://redirect.github.com/pnpm/pnpm/issues/14614">#14614</a>.</p>
</li>
<li>
<p>Large downloads over slow connections no longer time out while data is still arriving. <code>fetch-timeout</code> now limits how long a request can go without making progress <a href="https://redirect.github.com/pnpm/pnpm/issues/14604">#14604</a>.</p>
</li>
<li>
<p>Sped up installs in workspaces with many projects when reusing a warm global virtual store <a href="https://redirect.github.com/pnpm/pnpm/issues/14540">#14540</a>.</p>
</li>
<li>
<p><code>pnpm deploy</code> is faster in large workspaces and no longer fails with <code>ERR_PNPM_LOCKFILE_CONFIG_MISMATCH</code> when the project includes a <code>.pnpmfile.mjs</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/14539">#14539</a>, <a href="https://redirect.github.com/pnpm/pnpm/issues/14671">#14671</a>.</p>
</li>
<li>
<p><code>pnpm add --workspace &lt;pkg&gt;</code> works again. It saves the dependency with the <code>workspace:</code> protocol and links it from the workspace. The command fails if no workspace project provides the package <a href="https://redirect.github.com/pnpm/pnpm/issues/14602">#14602</a>.</p>
</li>
<li>
<p><code>pnpm add</code> and <code>pnpm install</code> now accept protocol-prefixed selectors such as <code>jsr:@scope/pkg</code>, <code>npm:pkg@^1.0.0</code>, and <code>workspace:pkg@*</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/14590">#14590</a>. Installs with JSR dependencies in the lockfile also no longer fail with <code>ERR_PNPM_META_FETCH_FAIL</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/14649">#14649</a>.</p>
</li>
<li>
<p>Boolean flags now accept explicit inline values. For example, <code>pnpm install --prod=false</code> installs devDependencies, while <code>--prod=true</code> skips them <a href="https://redirect.github.com/pnpm/pnpm/issues/14553">#14553</a>.</p>
</li>
<li>
<p><code>pnpm install &lt;pkg&gt;</code> now accepts <code>--offline</code> and <code>--prefer-offline</code>, as <code>pnpm add &lt;pkg&gt;</code> already did <a href="https://redirect.github.com/pnpm/pnpm/pull/14194">#14194</a>.</p>
</li>
<li>
<p>Fixed <code>pnpm install --frozen-lockfile</code> rejecting a freshly generated lockfile when overrides use relative <code>file:</code> or <code>link:</code> paths in a workspace <a href="https://redirect.github.com/pnpm/pnpm/issues/14555">#14555</a>.</p>
</li>
</ul>
