## Open format decision (gating step 1)

Step 1 says "first wire codec (JSON)" (my plan, Aaron-endorsed). One engineering
flag worth weighing before coding the codec: **CBOR (RFC 8949 deterministic) is
technically cleaner for a BYTE-LOCK than JSON** — CBOR has native types for all 8
DynamicValue cases (no Int/Float-both-are-number ambiguity; native byte-strings,
not base64) AND its deterministic-encoding spec (§4.2) defines **shortest-float**,
which SOLVES the cross-language float-canonicalization problem JSON leaves open.
JSON-as-byte-lock needs: Int=exact-decimal (BigInt in TS), Bytes=tagged/base64
convention, and either a cross-lang canonical-float decision or float-deferred-v1.
Default (Aaron-endorsed): proceed JSON-first, defer float. Alternative: CBOR for
the byte-lock, JSON as a separate interop codec. Surfaced to Aaron; proceed JSON
unless he picks CBOR. (Object stays ORDER-PRESERVING either way — DynamicValue.Object
is order-significant per #6492/#6494; the canonical encoding preserves insertion
order, deviating from CBOR §4.2 / JCS key-sorting, because our value is
order-significant; that's internal-byte-lock, not standard-interop.)
