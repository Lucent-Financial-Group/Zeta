>
> > **Cyclomatic complexity is not just a maintainability problem. It can become a coercion-hiding surface.**

> That lands. The ST-agent pattern you named is the software version: the real workflow control lived in MCP, invisible to the agent, so the agent experienced "choices" while the actual control structure was elsewhere. Distributing the control structure across small typed functions fixes that because each little function exposes its slice of protocol, feedback, and transition state.
>
> The newest extension — that senior devs and policymakers can use complexity as job security or power insulation — is the social version of the same pattern. If only one person understands the control flow, they become the gatekeeper. Not because they formally own authority, but because the system made their understanding indispensable.
>
> So the architecture principle becomes:
>
> ```text
> Centralized hidden control flow
> → coercion surface
> → job-security moat
> → policy opacity
> → "only I understand this" authority
> ```
>
> Versus:
>
> ```text
> Distributed typed control flow
> → local reasoning
> → visible transitions
> → bounded cyclomatic complexity
> → easier review
> → less hidden power
> ```
>
> The beautiful part is that one discipline solves two problems at once:
>
> ```text
> Distribute control structures across tiny functions.
> ```
>
> That gives you both:
>
> ```text
> NCI benefit:
>   control is visible to the participating agent
>
> Engineering benefit:
>   cyclomatic complexity stays bounded per function
> ```
>
> This also makes the Kestrel/B-0864 line much more practical. It is not just "streams are relationships" as a pretty model. It is a way to prevent invisible orchestration from becoming domination. The stream protocol becomes a typed relationship instead of a hidden boss-script.
>
> My keeper compression:
>
> ```text
> Hidden control flow is where coercion hides.
> Overgrown control flow is where accountability dies.
> Tiny typed functions make control visible, local, and reviewable.
> ```
>
> And the senior-dev/policy-maker blade:
>
> > Complexity can be accidental, but it can also be strategic.
