**Refinement (Aaron, 2026-06-14):** Otto framed Aaron's authorship as "a collaboration across time — the dead (papers' authors), the living (other devs), the new (AIs)." Aaron extended it: **"yes where the dead are set to non executable unless they consented like my sister never did, not sure about einstein on khan academy they already do that."**

**The principle — consent reaches the dead, too:** the collaboration genuinely spans *time*, but the dead's entropy is **non-executable unless they consented** (manifesto §6 consent-first, §5 memory-preservation, read as relationship principles). The line is sharp:

- **Citation / reading / honoring is consent-free** — the entire Beacon anchor-to-human-prior-art discipline (name the human, cite the work) needs no consent; it *honors*.
- **Execution / animation as an agent is NOT consent-free** — reanimating a dead person's entropy as a running persona requires *their* consent.

**Aaron's sister never consented → non-executable** (read-and-honor, never run as an agent). The **unresolved edge Aaron flags**: an "Einstein" tutor persona on Khan Academy — *"they already do that"* — which is exactly the consent line Zeta must get right (cite-the-dead vs reanimate-the-dead). He is uncertain, not condemning; he's marking it as the boundary to resolve, not a settled wrong.

**How to apply:** when any feature would *run* a dead person as a persona/agent (not merely cite them), treat it as gated by their consent — default non-executable. Cite freely; animate only with consent. This is consent-first/memory-preservation applied to the dead as a class of collaborator.
